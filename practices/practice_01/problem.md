# Проблема и метрики

## Проблема

- Пользователь: инженер/ревьюер, использующий сервис AI‑помощника для оценки PR по diff.
- Ситуация: сервис принимает diff и отправляет его в внешний LLM, возвращая комментарий.
- Что происходит сейчас: реализация в PR отправляет сырой diff в LLM без редакции секретов, без таймаута/контроля ошибок и возвращает упрощённый ответ. Это расходится с правилами SEC-1, REL-1 и OUT-1.
- Почему это мешает пользователю или бизнесу: риск утечки секретов (SEC-1), нестабильность и неопределённые сбои (REL-1), несогласованный контракт ответа, невозможность автоматизировать потребление результата (OUT-1).
- Что не входит в задачу: общая архитектура сервиса, аутентификация/авторизация, оптимизация стоимости LLM, асинхронизация — если это не требуется правилами.

## Метрики

Выберите измеримые показатели, относящиеся к проблеме. Не используйте VTG, IRR, WACC, CSAT или другую метрику только ради названия.

| Метрика | Текущее значение или способ замера | Целевое изменение | Когда измеряем | Источник данных |
|---|---:|---:|---|---|
| Доля ответов, соблюдающих OUT-1 (summary, ≤3 risks, checks) | 0% (возвращается только comment) | 100% | После правки API и сервиса | Интеграционный тест схемы ответа |
| Доля вызовов LLM, завершающихся контролируемым ответом при таймауте/ошибке (REL-1) | <100% (ошибка пробрасывается) | 100% при таймауте 10s | Интеграционный тест с эмуляцией таймаута | Тестовый double LLM |
| Доля случаев, когда секреты не покидают сервис (SEC-1) | Не гарантируется | 100% | Тест с искусственным секретом в diff | Юнит‑тест ReviewService |

## Почему изменение метрики подтвердит решение проблемы

OUT-1 фиксирует договорённость о формате и позволяет автоматически потреблять результат. REL-1 снижает сбои и повышает предсказуемость сервиса. SEC-1 исключает утечки секретов в внешний LLM.

## Как использовали AI

- Для чего:
  - Сформулировать проблему, выбрать прикладные метрики из правил CASE.md и привязать их к тестам.
- Тип промпта:
  - Аналитический, zero-shot на основе diff и правил SEC-1…QA-1.
- Строка в [`prompts.md`](prompts.md):
  - P1-01
- Что проверили и исправили сами:
  - Привели метрики к измеримому виду, исключили несвязанные предложения (валидация/аутентификация), не подтверждённые правилами.
