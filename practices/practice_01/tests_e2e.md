# E2E-проверки

| Сценарий пользователя | Предусловия | Действие | Наблюдаемый результат | Evidence |
|---|---|---|---|---|
| Позитивный: аудит типового PR | Сервис запущен, валидный diff < 20 000 символов без секретов | Отправка POST `/api/reviews` с телом diff | HTTP 200, структурированный JSON: непустое summary, массив risks (≤3 с file, line, evidence, risk) и массив checks | E2E-тест `test_e2e_successful_review_flow` |
| Негативный: отказ внешнего LLM / таймаут | Сервис запущен, эмулятор LLM отвечает с задержкой 12 с | Отправка POST `/api/reviews` с валидным diff | Контролируемый HTTP 503 ровно через 10 с (REL-1), тело ответа содержит понятное сообщение об ошибке, без трассировки стека | E2E-тест `test_e2e_llm_timeout_graceful_handling` |
| Граничный: diff с секретами и граничным размером | Сервис запущен, diff содержит 19 990 символов и тестовый JWT-токен | Отправка POST `/api/reviews` с телом | HTTP 200, в логах исходящего вызова токен заменён на `[REDACTED]`, в ответе сформированы риски без утечки секрета | E2E-тест `test_e2e_boundary_diff_with_secrets` |

## Как использовали AI

- Для чего: Составление сквозных пользовательских сценариев (позитивный, негативный, граничный)
- Тип промпта: RCTF (E2E спецификации)
- Строка в [`prompts.md`](prompts.md): P1-02
- Что проверили и исправили сами: Проверили обязательное наличие трех классов сценариев (позитивный, негативный, граничный) и их привязку к требованиям SEC-1, REL-1, OUT-1, API-1
