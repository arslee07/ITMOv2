# Правила для агентов (AGENTS.md)

## 1. СТРОГИЙ ПЕРИМЕТР РАБОЧЕГО ПРОСТРАНСТВА (КРИТИЧЕСКИ ВАЖНО)
* **НИКОГДА НЕ ВЫХОДИТЬ ЗА ПРЕДЕЛЫ КОРНЯ ПРОЕКТА** — директории, где лежит этот `AGENTS.md`.
* **Запрещено** читать, создавать, модифицировать или удалять любые файлы вне корня проекта.
* **Запрещено** использовать пути за пределами корня проекта (включая `/tmp`, `~`, `/home/ars/*`, системные директории).
* **Запрещены** команды смены директории (`cd`). Все команды должны выполняться строго внутри рабочего каталога.

---

## 2. ПРАВИЛА РАБОТЫ С GIT
* **Никаких запросов паролей или GPG-ключей**: 
  При выполнении коммитов **всегда** использовать флаг `--no-gpg-sign`:
  ```bash
  git commit --no-gpg-sign -m "feat/fix: описание изменений"
  ```
* Не запускать интерактивные команды git, требующие ручного ввода в терминале (pinentry, pass, ssh password prompts).

---

## 3. СТАНДАРТЫ КОДА (GO BACKEND)
Соблюдать правила установленных скиллов `writing-go`, `golang-code-style` и `golang-testing`:
* **Stdlib first**: использовать исключительно стандартную библиотеку Go (`net/http`, `html/template`, `embed.FS`, `sync`, `encoding/json`). Никаких тяжелых фреймворков (Gin, Fiber, Chi, Echo) без прямого указания пользователя.
* **Современный Go 1.25+**: применять встроенный роутинг `net/http.ServeMux` с методами (`GET /path`), `context` во всех сетевых вызовах.
* **Чистый код и типы**:
  * Возвращать конкретные структуры, принимать интерфейсы только по необходимости на стороне потребителя.
  * Явная обработка ошибок с контекстом: `fmt.Errorf("call mcp tool: %w", err)`.
  * Не использовать `panic` в рабочей логике.
  * Чистый форматированный код (`gofmt` / `go vet`).
* **Тестирование**:
  * Обязательные табличные тесты (`table-driven tests`).
  * Все тесты должны запускаться через `go test ./...` и отрабатывать быстро.

---

## 4. СТАНДАРТЫ UI/UX И ФРОНТЕНДА
Соблюдать правила установленных скиллов `ui-ux-pro-max` и `web-design-guidelines`:
* **Стек фронтенда**: Go `html/template` + **HTMX** (для динамических партиалов) + **Alpine.js** (для легковесного клиентского состояния) + **Leaflet.js** (для интерактивных карт). Никаких тяжелых SPA-фреймворков (React, Angular).
* **Дизайн-система**:
  * Фирменная палитра ВкусВилл: основной зеленый `#008248`, вспомогательный лайм/акцент `#22c55e`, чистый контрастный фон.
  * Никаких сырых эмодзи в роли интерфейсных иконок — использовать только аккуратные векторные SVG с `aria-hidden="true"`.
  * Минимальный размер кликабельных элементов (тач-таргетов) — 44×44px.
* **Доступность (Accessibility)**:
  * Все иконки-кнопки обязаны содержать понятный `aria-label`.
  * Интерактивные элементы обязаны иметь видимый фокус `:focus-visible` (не убирать outline без замены).
  * Поддержка клавиатуры (`Enter` / `Space`) на интерактивных карточках.

## 5. ИНТЕГРАЦИЯ С MCP ВКУСВИЛЛ
* Транспорт: HTTP POST JSON-RPC 2.0 на `https://mcp.vkusvill.ru/mcp`.
* Обязательные заголовки: `Content-Type: application/json`, `Accept: application/json, text/event-stream`, реалистичный `User-Agent` (защита QRATOR).
* Лимиты: MCP-сервер защищен лимитом 60 req/min. Все повторные запросы фильтров и магазинов **обязаны проходить через in-memory кэш**.
* Фоновый прогрев каталога (`internal/mcp/warmer.go`) обязан держать паузу не меньше ~1.1с между запросами (≤ ~54 req/min) и не обходить кэш.

## 6. АВТОМАТИЧЕСКИЕ ПРОВЕРКИ И RUNNER
* **Runner проекта — `make test`** (полный `go test ./...`); быстрые проверки — `gofmt -l .` и `go vet ./...`.
* **Git-хуки** лежат в `.githooks/` и включаются командой `make init-hooks` (выставляет `core.hooksPath=.githooks`):
  * `pre-commit` — блокирует коммит при неотформатированном коде (`gofmt -l`), ошибках `go vet` или падающих тестах;
  * `commit-msg` — требует формат Conventional Commits.
* **Автопроверка после правок** реализована OpenCode-плагином `.opencode/plugins/vv-checks/` через hook `tool.execute.after`: после `edit`/`write`/`patch` по `.go`-файлу он запускает `gofmt`/`go vet`/`go test` и дописывает результат в вывод инструмента, поэтому агент сразу видит поломку, не дожидаясь коммита.

## 7. СОБСТВЕННЫЙ MCP-СЕРВЕР (vvmcp)
* Свой MCP-сервер проекта — `cmd/vvmcp` (stdio, JSON-RPC 2.0). Подключается в `opencode.json` → `mcp.servers.vvmcp` командой `go run ./cmd/vvmcp`.
* Экспонирует один tool **`audit_templates`**: статическая проверка HTML-шаблонов на правила §4 (svg без `aria-hidden`, кнопка-иконка без доступного имени, сырые эмодзи). Логика — `internal/audit`, покрыта table-driven тестами.
* Сквозная проверка сервера — `.agents/skills/vv-mcp-verify/scripts/verify_mcp.sh` (initialize → tools/list → успешный и ошибочный `tools/call`).
* В отличие от внешнего MCP ВкусВилла (§5), этот сервер ничего не отправляет в сеть: он читает только локальные файлы проекта.
