# AGENTS.md — консоль триажа

## Что это

Учебный проект практики 08: фронтенд к ассистенту поддержки из практики 07.2.
Пользователь отправляет баг-репорт, классификатор определяет тип (`bug`, `task`, `feature`),
при уверенности ниже 0.8 тикет уходит в `needs-triage`. Тикет появляется в очереди,
детали открываются в диалоге.

## Команды

```bash
npm install
npm run dev      # Vite на 5173 + API на 8787
npm test         # все клиентские тесты
npm run build    # typecheck + production-сборка
npm start        # API + статика из dist на 8787
```

## Правила

- Никаких коммитов и пушей без явной просьбы. Сейчас работа идёт локально.
- Секреты только в `.env`. В README и код ключи не попадают.
- Компоненты берём из `src/components/ui` (shadcn/ui). Новые не дублируем.
- Цвета, шрифт, радиусы и отступы — только через токены в `src/index.css`.
- Все поля с `Label`, ошибки с `role="alert"`, фокус видимый, сценарий проходится с клавиатуры.
- Ответы сервера в тестах подменяются через MSW (`src/test`). `npm test` должен быть зелёным целиком.
- Повторная отправка во время запроса блокируется `useRef` и `disabled`; это поведение покрыто тестом.

## Скиллы

Перед правкой интерфейса загрузи `frontend-design` и `web-design-guidelines`.
Перед тестами — `webapp-testing`. Перед заявлением, что всё готово, — `verification-before-completion`.
Любой русский текст длиннее подписи кнопки прогоняй через `slopotron`: без канцелярита,
промо-лексики и шаблонных зачинов. Коротко, конкретно, с глаголом.

## Архитектура

- `src/App.tsx` — загрузка списка, создание тикета, сообщение об успехе, выбор тикета.
- `src/features/tickets` — форма, список, карточка, диалог, валидация и подписи.
- `src/api/tickets.ts` — typed-клиент `fetch`, ошибки `ApiError` с полями формы.
- `server/api.mjs` — реальный API: валидация, классификатор (эвристика / VseLLM / n8n), JSON-хранилище.
- `server/server.mjs` — API и статика для production.
- `scripts/dev.mjs` — одновременно API и Vite.
- `mockups/v0/app/page.tsx` — экспорт прототипа из v0, по нему сверяется интерфейс.
- `mockups/screens/` — пять состояний прототипа.
- `docs/screens/` — скриншоты рабочего интерфейса с реальным API.
