# Спецификация: консоль триажа обращений

## Кто пользуется и зачем

Агент поддержки разбирает входящие баг-репорты. Ему нужно быстро понять, что перед ним:
ошибка, задача или новая возможность. Форма отправляет текст в классификатор, а очередь
показывает результат; из карточки можно взять тикет в работу.

## Основной сценарий

1. Пользователь открывает консоль. Очередь пустая, видно «Пока нет обращений».
2. Заполняет «Заголовок», «Описание», «Автор».
3. Нажимает «Отправить обращение».
4. Пока идёт запрос, кнопка показывает «Классифицируем…», поля и кнопка disabled.
5. После ответа форма очищается, в форме появляется сообщение «Тикет создан: …»,
   а карточка тикета встаёт первой в очереди.
6. Пользователь нажимает «Подробнее», открывается диалог с полным текстом и метаданными.
7. В диалоге можно нажать «Взять в работу», статус меняется на «В работе».

## Состояния интерфейса

| Состояние | Что видно |
|---|---|
| Исходное | Пустая очередь, форма пустая |
| Ввод | Заполненные поля, ошибок нет |
| Загрузка | Кнопка «Классифицируем…», spinner, поля disabled, скелетоны в очереди |
| Успех | Зелёное сообщение, новая карточка первой, форма очищена |
| Ошибка отправки | Красный alert, текст ошибки, кнопка «Повторить», ввод сохранён |
| Ошибка загрузки | Alert «Не удалось загрузить обращения», кнопка «Повторить» |
| Пусто | «Пока нет обращений» |

## Валидация

| Поле | Правило | Сообщение |
|---|---|---|
| Заголовок | обязателен, 3–120 символов | «Укажите заголовок обращения.» / «Заголовок должен быть не короче 3 символов.» |
| Описание | обязательно, 10–4000 символов | «Опишите проблему или предложение.» / «Описание должно быть не короче 10 символов.» |
| Автор | обязателен, 2–60 символов | «Укажите, кто отправил обращение.» / «Имя автора должно быть не короче 2 символов.» |

Пробелы по краям обрезаются. Строка из одних пробелов считается пустой.
Ошибка появляется под полем, `role="alert"`, связана через `aria-describedby`.
Фокус переходит на первое неверное поле.

## API

`POST /api/tickets`

```json
{ "title": "…", "description": "…", "author": "…" }
```

Успех `201`:

```json
{
  "ticket": {
    "id": "tkt_…",
    "title": "…",
    "description": "…",
    "author": "…",
    "type": "bug",
    "confidence": 0.94,
    "classifier": "llm",
    "label": "bug",
    "status": "triaged",
    "createdAt": "2026-11-25T00:00:00.000Z",
    "updatedAt": "2026-11-25T00:00:00.000Z"
  }
}
```

Ошибка валидации `422`:

```json
{ "error": { "code": "VALIDATION_ERROR", "message": "Проверьте заполнение полей.", "fields": { "title": "…" } } }
```

Ошибка классификатора `503`:

```json
{ "error": { "code": "CLASSIFIER_UNAVAILABLE", "message": "Классификатор временно недоступен. …" } }
```

`GET /api/tickets` → `{ "tickets": [ … ] }`, новые первыми.
`PATCH /api/tickets/:id` с `{ "status": "in-progress" | "closed" }` → `{ "ticket": … }`.

Правило классификации: `confidence < 0.8` или тип `unknown` → `status: "needs-triage"`,
`label: "needs-triage"`. Иначе `status: "triaged"`, `label` равен типу.

## Повторная отправка

Пока запрос не завершён, повторный submit не создаёт второй запрос. Защита двойная:
`disabled` на кнопке и полях, плюс синхронный `useRef`-замок в обработчике. Это поведение
проверяется тестом: три submit подряд во время ожидания, счётчик POST равен 1.

## Доступность

- У каждого поля есть `<Label htmlFor>`.
- Ошибки с `role="alert"`, поля с `aria-invalid` и `aria-describedby`.
- Все действия доступны с клавиатуры, фокус виден (`focus-visible:ring`).
- Диалог закрывается по Escape и кнопкой «Закрыть», фокус возвращается на триггер.
- На узком экране колонки складываются в одну, элементы управления остаются доступны.
