# Часть 2 — правило OpenSpec для проекта

## Что сделано

1. Создан следующий change `add-shop-sort` (сортировка списка магазинов) и
   черновик `design.md` без диаграммы — это фрагмент «до».
2. В `openspec/config.yaml` добавлено постоянное правило (в существующий блок,
   второй `rules` не создавался):

   ```yaml
   rules:
     design:
       - Объясни взаимодействие диаграммой Mermaid.
   ```

3. Выполнено `openspec instructions design --change add-shop-sort --json`:
   в ответе появилось поле `rules: ["Объясни взаимодействие диаграммой Mermaid."]`,
   то есть правило попадает в будущие инструкции (файл `instructions-after.json`).
4. То же место дизайна переписано: вместо нумерованного списка — Mermaid-диаграмма
   плюс краткое текстовое описание. Смысл и границы сохранены.

## Файлы

| Файл | Что это |
|---|---|
| `config-before.yaml` | конфиг без правила |
| `config-after.yaml` | конфиг с правилом |
| `instructions-before.json` | `openspec instructions design` до правила — поля `rules` нет |
| `instructions-after.json` | после правила — `rules` содержит пункт про Mermaid |
| `design-before.md` | фрагмент дизайна до применения правила |
| `design-after.md` | тот же фрагмент после правила |
| `design.diff` | diff «до/после» |

## Проверка смысла

- Шаги взаимодействия те же: select → сохранение выбора → `renderList` →
  `arrangedShops` → сортировка → карточки; кнопка геолокации включает `distance`.
- Диаграмма — Mermaid `flowchart LR`, открывается в mermaid.live.
- Код не менялся (правило применено только к документу дизайна).
