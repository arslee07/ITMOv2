# Team 2 — спецификация логики: экспорт магазинов в CSV

**Feature Branch**: `001-export-shops-csv`

**Created**: 2026-10-25

**Status**: Draft

**Вход**: «Выгрузить текущую выборку магазинов в файл, данные и алгоритм — моя зона»

## Назначение

Сервер собирает CSV из накопленного кэша магазинов, применяя те же фильтры, что
и список в интерфейсе, и отдаёт файл одним HTTP-ответом. Файл не кэшируется.

## User Scenarios & Testing

### User Story 1 - Сервер отдаёт файл выборки (Priority: P1)

Клиент запрашивает `/api/export.csv` с теми же фильтрами, что и список, и получает
готовый CSV.

**Independent Test**: `curl` с фильтром по городу возвращает `200`, заголовок
`text/csv` и строки только этого города.

**Acceptance Scenarios**:

1. **Given** в кэше 10 магазинов двух городов, **When** запрошен экспорт с
   `city_id=6423`, **Then** в файле только магазины Москвы.
2. **Given** в кэше есть магазины, **When** запрошен экспорт без параметров,
   **Then** в файле все накопленные магазины.
3. **Given** кэш пуст, **When** запрошен экспорт, **Then** ответ `200` и файл,
   состоящий только из строки заголовка.

### User Story 2 - Корректный CSV для Excel (Priority: P2)

Пользователь открывает файл в Excel или LibreOffice без «кракозябр» и сдвинутых
колонок.

**Independent Test**: открыть файл в LibreOffice — кириллица читается, колонки на
местах, адрес с `;` и кавычками не разъезжается.

**Acceptance Scenarios**:

1. **Given** адрес содержит `;` и `"`, **When** магазин попадает в файл, **Then**
   поле экранировано по RFC 4180 (кавычки удвоены, поле в кавычках).
2. **Given** файл открыт в Excel, **When** он загружен, **Then** UTF-8 BOM делает
   кириллицу читаемой.

### User Story 3 - Ошибки ввода не ломают экспорт (Priority: P3)

Клиент передал битые параметры — сервер отвечает `400` с текстом, а не пустым
файлом.

**Independent Test**: `curl "/api/export.csv?city_id=abc"` → `400`, тело содержит
`city_id`.

**Acceptance Scenarios**:

1. **Given** `city_id=abc`, **When** запрошен экспорт, **Then** ответ `400` и имя
   параметра в теле.
2. **Given** `lat` без `lon`, **When** запрошен экспорт, **Then** ответ `400`.

## Requirements

### Functional Requirements

- **FR-001**: Endpoint MUST быть `GET /api/export.csv`.
- **FR-002**: Параметры фильтра MUST совпадать с `/api/shops/points`: `city_id`,
  `feature_id`, `region_id`, `subway_id`, `q`, `lat`, `lon`. Валидация MUST быть
  общей с существующей (те же коды и сообщения).
- **FR-003**: Фильтрация MUST повторять правила списка: город, регион, метро,
  удобство, поиск по адресу или метро (без учёта регистра).
- **FR-004**: Ответ MUST иметь `Content-Type: text/csv; charset=utf-8`,
  `Content-Disposition: attachment; filename="vkusvill-shops-<YYYY-MM-DD-HHMM>.csv"`
  и `Cache-Control: no-store`.
- **FR-005**: Файл MUST начинаться с UTF-8 BOM.
- **FR-006**: Разделитель полей — `;`, конец строки — CRLF, экранирование по
  RFC 4180 (`"` → `""`, поле с `;`, `"`, CR или LF — в кавычках).
- **FR-007**: Колонки и порядок MUST быть: `ID;Адрес;Город;Рейтинг;Широта;Долгота;Метро;Удобства;Расстояние`.
- **FR-008**: При известных координатах MUST заполняться `Расстояние` (в метрах
  или километрах, как в интерфейсе) и строки MUST сортироваться по возрастанию
  расстояния; магазины без координат MUST идти в конце по `ID`; без координат
  пользователя строки сортируются по `ID`.
- **FR-009**: Пустые значения (нет рейтинга, метро, удобств) MUST записываться как
  пустое поле, без `null` и без прочерка.
- **FR-010**: Списки метро и удобств MUST объединяться через запятую с пробелом
  внутри поля.
- **FR-011**: Экспорт MUST NOT обращаться к MCP: источник — только накопленный кэш.
- **FR-012**: Если подходящих магазинов больше 20 000, сервер MUST ответить `413`
  с сообщением о превышении лимита.

### Key Entities

- **Строка CSV**: один магазин из кэша с вычисленным расстоянием (если есть
  координаты).
- **Заголовок**: фиксированный набор колонок из FR-007.

## Success Criteria

- **SC-001**: 1000 магазинов выгружаются быстрее чем за 1 секунду на локальной
  машине.
- **SC-002**: Файл открывается в LibreOffice без предупреждений о кодировке.
- **SC-003**: Количество строк файла равно количеству магазинов текущей выборки
  плюс один заголовок.

## Assumptions

- Кэш уже прогрет фоновым обновлением; экспорт не ждёт полного прогрева.
- Лимит 20 000 строк достаточен для текущего каталога (несколько тысяч магазинов).
