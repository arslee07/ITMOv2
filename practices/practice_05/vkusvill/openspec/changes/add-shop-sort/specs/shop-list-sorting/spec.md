# Spec Delta

## Purpose

Дать пользователю явное управление порядком списка магазинов и сохранять выбор
между визитами, не меняя серверный контракт.

## ADDED Requirements

### Requirement: Выбор порядка списка

Список магазинов SHALL поддерживать порядок по расстоянию, по рейтингу и по
адресу. По умолчанию MUST применяться порядок по адресу.

#### Scenario: Выбор порядка по рейтингу
- **WHEN** пользователь выбирает «по рейтингу»
- **THEN** магазины с более высоким рейтингом идут раньше, магазины без рейтинга — в конце

#### Scenario: Порядок по умолчанию
- **WHEN** пользователь открывает страницу впервые
- **THEN** список упорядочен по адресу

### Requirement: Порядок по расстоянию зависит от координат

Пункт «по расстоянию» MUST быть недоступен, пока координаты пользователя не
известны. После получения координат MUST применяться сортировка по возрастанию
расстояния.

#### Scenario: Нет координат
- **WHEN** страница открыта без геолокации
- **THEN** пункт «по расстоянию» недоступен, активен порядок по адресу

#### Scenario: Координаты появились
- **WHEN** пользователь нажимает «Рядом со мной» и получает координаты
- **THEN** пункт «по расстоянию» становится доступен без перезагрузки страницы

### Requirement: Сохранение выбора

Выбранный порядок MUST сохраняться локально и восстанавливаться при следующем
открытии страницы. Недоступный сохранённый порядок MUST заменяться порядком по
адресу, а не ломать список.

#### Scenario: Возврат на страницу
- **WHEN** пользователь выбрал «по рейтингу» и перезагрузил страницу
- **THEN** список снова упорядочен по рейтингу

#### Scenario: Сохранён «по расстоянию», координат нет
- **WHEN** страница открыта без геолокации, а в сохранении «по расстоянию»
- **THEN** применяется порядок по адресу без ошибок в консоли
