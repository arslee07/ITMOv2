# Proposal

## Why

Сейчас `parseQueryParams` молча проглатывает мусор в query-параметрах: ошибка
`strconv.Atoi` превращается в `0`, то есть в «все города / без фильтра».
Битый deep link или опечатка в ссылке дают правдоподобный, но неверный список
магазинов, и пользователь не понимает, почему фильтр не применился. Хуже того,
такой запрос всё равно уходит в MCP ВкусВилл и тратит лимит 60 запросов в минуту
(см. `AGENTS.md` §5).

## What Changes

- Добавить проверку входных параметров фильтра до обращения к кэшу и MCP:
  `page`, `city_id`, `feature_id`, `region_id`, `subway_id`, `lat`, `lon`, `q`.
  Режим `GET /api/shops/points?scope=all` в проверку не входит: он отдаёт
  накопленный кэш и фильтры игнорирует.
- Некорректный ввод возвращает `400 Bad Request` с сообщением на русском,
  в котором назван конкретный параметр и причина отказа.
- Валидные и отсутствующие параметры обрабатываются ровно как раньше,
  включая прежние приведения (`page < 1` → `1`, пустые id → `0`).
- Частично заданные координаты (`lat` без `lon` или наоборот) и значения вне
  допустимых диапазонов считаются ошибкой ввода.
- Поисковая строка `q` обрезается по краям, ограничивается 100 рунами и
  отвергает управляющие символы.
- Ошибочный запрос не обращается к MCP и не расходует лимит.

Не входит в изменение: переработка клиентского рендеринга списка, новые
фильтры, изменение формата успешного ответа, кэширование.

## Capabilities

### New Capabilities

- `shop-filtering`: разбор и проверка query-параметров фильтра магазинов
  (`/`, `/shops`, `/api/shops/points`) и контракт ошибок ввода.

### Modified Capabilities

Нет: существующего каталога specs у проекта пока нет, поведение успешных
запросов не меняется.

## Impact

- `internal/web/handlers.go` — разбор параметров, валидация, ответы об ошибках.
- `internal/web/handlers_test.go` — табличные тесты на валидацию и на отсутствие
  обращений к MCP при ошибке.
- `cmd/server/main.go` — без изменений маршрутов; обработчики остаются те же.
- Внешний контракт: `GET /`, `GET /shops`, `GET /api/shops/points` начинают
  возвращать `400` на некорректные параметры вместо «тихого» успеха.
