# Шаг 1 — explore (до спеки)

**Фича**: валидация параметров фильтра (`validate-filter-input`).

## Что уже есть

- `internal/web/handlers.go`: `parseQueryParams` — единственная точка разбора
  query-параметров для `HandleIndex`, `HandleShops`, `HandleShopsPoints`.
- Ошибки `strconv.Atoi`/`ParseFloat` игнорируются, значения подменяются нулями.
- `buildPageData` сразу идёт в `StoreCache` и MCP, поэтому «мусорный» запрос
  расходует лимит 60 req/min (см. `AGENTS.md` §5).
- Тесты: табличные, без сети (`internal/web/handlers_test.go`), покрывают только
  `marshalASCII` и `shopPoint`.
- `app.js` фильтрует список на клиенте; серверный `/shops` в текущих шаблонах не
  используется (нет `hx-get`).
- Режим `/api/shops/points?scope=all` отдаёт накопленный кэш и не смотрит на
  фильтры.

## Команда проверки и baseline

```bash
make test      # go test ./... — 5 пакетов, всё зелёное до изменения
go build ./...
```

## Границы изменения

Входит: разбор и проверка параметров, ответы 400, тесты, README.
Не входит: клиентский рендеринг, новые фильтры, формат успешных ответов,
кэширование, маршруты.

## Условия приёмки (3–5)

1. `city_id/feature_id/region_id/subway_id`: только целое ≥ 0; пусто = без фильтра.
2. `page`: `< 1` → 1; нецелое/нечисловое → 400.
3. `lat`/`lon`: только парой, конечные числа, в диапазонах; `0,0` валиден.
4. `q`: обрезка, ≤ 100 рун, без управляющих символов; иначе 400.
5. Ошибка — `400 text/plain` с именем параметра, без обращения к MCP.

## Что сохраняем

- Успешные ответы и их формат не меняются.
- `page=0` и отсутствие параметров работают как раньше.
- `scope=all` продолжает игнорировать фильтры.
