# RAG

- Вопрос к источникам: «Каковы точные требования к схеме ответа сервиса (OUT-1), правила логирования
  (OBS-1) и почему текущая реализация в TRAINING_PR.diff им не соответствует?»

## Разрешённые источники

| Файл или документ | Зачем нужен | Какой фрагмент используем |
|---|---|---|
| practices/practice_01/CASE.md | Первоисточник правил репозитория | Правила OUT-1 (структура
  ответа), QA-1 (доказанность) и OBS-1 (политика логирования) |
| practices/practice_01/TRAINING_PR.diff | Код текущей реализации | app/review_service.py:22 (return
  {"comment": answer}) |

## Запрос

Используя исключительно приложенные фрагменты CASE.md и TRAINING_PR.diff, ответь:
1. Какова точная схема ответа по правилу OUT-1?
2. Какие данные запрещено писать в лог по правилу OBS-1?
3. В чём конкретно выражается несоответствие app/review_service.py:22 правилу OUT-1?
Каждое утверждение сопроводии точной ссылкой на источник. Не используй информацию вне источников.

## Ответ со ссылками на источники

1. Схема ответа (CASE.md, правило OUT-1):
   Ответ обязан содержать поля `summary`, массив `risks` и массив `checks`. В массиве `risks`
  допускается максимум 3 элемента, каждый с обязательными полями: `file`, `line`, `evidence`, `risk`.
2. Политика логирования (CASE.md, правило OBS-1):
   В лог разрешено писать только `request_id`, длительность запроса и HTTP-статус. Содержимое diff и
  тело ответа модели логировать категорически запрещено.
3. Несоответствие реализации (TRAINING_PR.diff, app/review_service.py:22):
   Метод возвращает словарь `{"comment": answer}`. Поля `summary`, `risks` и `checks` отсутствуют,
  что является прямым нарушением OUT-1.
