# Tree of Thoughts

- Решение, для которого нужны альтернативы: Стратегия обнаружения и маскирования секретов в diff
  (SEC-1) перед отправкой во внешний LLM.
- Критерии выбора:
  1. Безопасность и надёжность маскирования (Coverage).
  2. Влияние на задержку ответа (Latency overhead, лимит < 5 мс).
  3. Сохранение целостности diff (отсутствие ложных срабатываний на git sha и пути).
  4. Автономность (отсутствие внешних сетевых зависимостей и GPU).

## Запрос

Сформулируй 3 архитектурные стратегии санитизации diff:
A: Heavy ML-based NER/Entropy scanner (нейросетевой детектор + энтропия).
B: Deterministic Regex-first + Allowlist (скомпилированные регулярные выражения по известным
  префиксам с исключением 40-hex git sha).
C: External Cloud DLP API (вызов стороннего сервиса сканирования секретов).
Сравни альтернативы по критериям и выбери одну для реализации.

## Внешне описанные альтернативы

| Альтернатива | Плюсы | Минусы | Оценка по критериям |
|---|---|---|---|
| A: ML / Entropy Scanner | Находит нестандартные секреты без префиксов | Высокий overhead (500–1000 мс), требует GPU, частые ложные срабатывания на скомпилированных данных и хэшах коммитов | 6/10 (не проходит по latency и стабильности diff) |
| B: Regex-first + Allowlist | Экстремальная скорость (<1 мс), детерминизм, 0 внешних зависимостей, отсутствие ложных срабатываний на git sha | Требует явной базы префиксов (ghp_, glpat_, eyJ, RSA keys), не ловит неструктурированные пароли | 9/10 (победитель: максимальная скорость и надежность для MVP) |
| C: External Cloud DLP API | Обширная готовая база сигнатур | Лишний сетевой hop (+200-500 мс), риск недоступности, передача чувствительных данных стороннему вендору | 5/10 (нарушает изоляцию периметра и увеличивает задержку) |

## Выбор

- Выбранная альтернатива: Альтернатива B (Deterministic Regex-first + Allowlist).
- Почему: Обеспечивает выполнение SEC-1 без накладных расходов по времени (<1 мс против 10 с общего
  бюджета), не требует GPU и исключает порчу структуры git diff.
- Как проверим: Юнит-тест с замером времени санитизации на максимальном diff (20 000 символов) —
  задержка не превышает 5 мс.
