# Few-shot

- Артефакт Практики 1: practices/practice_01/adr.md (раздел «Решение: санитизация секретов SEC-1»)
- Что хотим улучшить: Задать модели точный формат маскирования секретов через примеры «Хорошо / Плохо», чтобы отличать реальные токены от git commit sha и путей к файлам.

## Примеры

### Хороший результат

Вход: diff с `Authorization: Bearer ghp_aBcD1234567890` и коммитом `commit 4b825dc642cb6eb9a060e54bf8d69288fbee4904`
Выход: `Authorization: Bearer [REDACTED_GH_TOKEN]`, а sha коммита `4b825dc642cb6eb9a060e54bf8d69288fbee4904` оставлен без изменений.

### Плохой результат

Вход: тот же diff.
Выход: `Authorization: Bearer ***` и `commit [REDACTED]` (замаскирован валидный git sha, разрушена структура diff).

## Запрос

Сформулируй правила и регулярные выражения для модуля Sanitizer (SEC-1) в adr.md, опираясь на хорошие и плохие примеры выше.

## Что получили

Модель предложила раздельные паттерны для известных префиксов токенов (ghp_, glpat-, eyJ/JWT, BEGIN PRIVATE KEY) и явно исключила 40-символьные hex-строки коммитов из маскирования.

## Что изменили в исходном артефакте

- Файл и раздел: practices/practice_01/adr.md, подраздел «2. Санитизация (Sanitizer)»
- Изменение: Добавлены спецификации регулярных выражений для токенов и правило сохранения 40-символьных git commit sha.
- Как проверили: Юнит-тест с diff, содержащим одновременно ghp_токен и git sha коммита.
- Что отклонили: Идею маскировать все строки энтропией выше 4.5 (слишком много ложных срабатываний на скомпилированных ассетах).
