# Chain of Verification

- Проверяемый черновик или утверждение: Черновик замечаний первичного ревью: «1. В POST /api/reviews
  нет аутентификации JWT; 2. В app/review_service.py:20 сырой diff передаётся в LLM без очистки токенов;
  3. Не соблюдены стандарты PEP-8 в именовании; 4. Нет проверки размера diff на 20 000 символов (API-1)».

## Запрос на проверку
Для каждого из 4 утверждений черновика задай проверочный вопрос:
1. Подтверждено ли требование правилами репозитория в CASE.md (SEC-1..QA-1)?
2. Есть ли конкретная строка и цитата в TRAINING_PR.diff?
Удали утверждения без строгого evidence и верни только подтвержденный список.

## Вопросы проверки и evidence

| Вопрос | Источник или проверка | Результат |
|---|---|---|
| Требуется ли аутентификация JWT правилами репозитория? | CASE.md, раздел «Правила репозитория» | Нет. В CASE.md нет правил об аутентификации, в problem.md она явно исключена из границ. Утверждение отклонено. |
| Есть ли доказательство передачи секретов в LLM? | TRAINING_PR.diff, app/review_service.py:20 | Да. Строка `prompt = f"...{diff}"` вставляет сырой diff. Нарушено правило SEC-1. Утверждение подтверждено. |
| Регламентирует ли контракт репозитория форматирование PEP-8? | CASE.md, раздел правил и границ | Нет. Внешние стилистические правила не входят в скоуп задачи (QA-1). Утверждение отклонено. |
| Отсутствует ли проверка лимита 20 000 символов? | TRAINING_PR.diff, app/api.py:35-38 и правило API-1 | Да. Эндпоинт принимает payload["diff"] без валидации длины. Нарушено правило API-1. Утверждение подтверждено. |

## Исправленный результат
Оставлены только два строго доказанных замечания:
1. app/review_service.py:20 — нарушение SEC-1: отправка сырого diff без санитизации токенов и ключей.
2. app/api.py:35-38 — нарушение API-1: отсутствие проверки длины входящего diff (> 20 000 символов).
